# 车机 蓝牙旋钮配件 · 最小硬件调试方案（无外壳）

> 目标：用**最少的钱、最快的速度**搭一套可上手调试的硬件，跑通
> 「**屏幕显示 UI + 旋钮旋转切功能 + 按压确认 + 屏幕本地模拟回显**」这条核心交互链。
> 本次**不连车机**、**不要外壳**、**不做 BLE**，先把"手头这套硬件 + 交互逻辑"验证活。
> 主控方案：**ESP32-S3 开发板 + GC9A01 圆形屏 + EC11 编码器（带按压）**。

---

## 0. 一句话方案

买 **3 样东西**（开发板 + 圆形屏 + 编码器），用**杜邦线接在面包板**上，
跑一个基于 **X-Knob 的 LVGL + GC9A01 驱动**、适配 **EC11** 的最小固件：
屏幕显示温度/风量等模拟值，旋转 EC11 切档位/调数值，按压 EC11 确认切换。
全程 USB 供电，不需要电池、外壳、无刷电机。

## 2. 接线表（ESP32-S3 DevKit → 屏 + EC11）

> ⚠️ 自制 PCB（ESP32-S3-WROOM-1 MCN16R8）因布线空间改了部分引脚，`firmware/include/config.h` 按 `BOARD_PCB` / `BOARD_DEVKIT` 宏分两组引脚（`platformio.ini` 里 env 名带 `_pcb` / `_devkit` 后缀选板子，主程序是 `pcb` / `devkit`）。自制板的完整接线见 §2.3。GPIO45 是 VDD_SPI 启动选择脚，板上按键线焊了 10kΩ 外部上拉（R5），按手册上电被拉高会把 Flash 供电切到 1.8V；但焊着 R5 也能正常启动——`espefuse summary` 确认（2026-10-20）模块出厂已烧 `VDD_SPI_FORCE=1`、`VDD_SPI_TIEH=1`，供电由 eFuse 固定 3.3V、不看 GPIO45。依据 ESP32-S3-WROOM-1/1U 数据手册 v1.8 第 8 章：带 PSRAM 的模块出厂都以 eFuse 固定 VDD_SPI，不受 GPIO45 影响；不带 PSRAM 的型号（N4/N8/N16）没烧，换用那种模块必须拆 R5。经原生 USB 烧录后芯片会停在下载模式，需手动按一次 EN 复位才运行新固件。DevKit 保持本节下表的原接线不变，编译时选 `_devkit` 的 env 即可（不开 USB CDC，日志仍走板载 COM 口）。

### 2.1 GC9A01 圆形屏（SPI）

> 使用 ESP32-S3 的 SPI2（默认 FSPI）硬件 SPI，参考 X-Knob 的 Arduino_HWSPI 接线。
> 开发板引脚可能与 X-Knob 定制 PCB 不同，这里给通用映射（按你的板子丝印调整）。

| GC9A01 引脚 | ESP32-S3 引脚 | 说明 |
|------------|--------------|------|
| SCL / SCK | GPIO12 | SPI 时钟（X-Knob: SCLK=12） |
| SDA / MOSI | GPIO11 | SPI 数据（X-Knob: MOSI=11） |
| CS | GPIO10 | 片选（X-Knob: TFT_CS=10） |
| DC | GPIO14 | 数据/命令（X-Knob: TFT_DC=14） |
| RST | GPIO9 | 复位（X-Knob: TFT_RST=9） |
| BLK / LED | GPIO13 | 背光（X-Knob: TFT_BLK=13），PWM 可调亮度 |
| VCC | 3.3V | 供电 |
| GND | GND | 地 |

> 如果买的屏是 6 引脚（无 BLK），背光引脚可省。

### 2.2 EC11 旋转编码器（带按键）

| EC11 引脚 | ESP32-S3 引脚 | 说明 |
|----------|--------------|------|
| A（CLK） | GPIO4 | 编码器相位 A |
| B（DT） | GPIO5 | 编码器相位 B |
| SW（按键） | GPIO6 | 按压开关，`INPUT_PULLUP`，按下接地 |
| +（VCC） | 3.3V | 公共端 |
| GND | GND | 地 |

> EC11 一般 5 个脚：A/B/公共端 + 按键 SW/公共端。A/B 用中断或轮询消抖读取。

### 2.3 自制 PCB 接线（来自 EDA 工程）

> 依据：仓库内 `hardware/SEP26/pcb/` 下的嘉立创 EDA 专业版工程 `KNOB_BOARD_SEP26.epro2`（工程名 KNOB_BOARD，编辑器 3.2.186）的 PCB 网表，同目录有原理图 PDF、PCB 图和交互式 BOM；模块焊盘号→GPIO 取自工程内的模块符号（2026-10-21 核对）。`config.h` 的 `BOARD_PCB` 分支与下表逐条一致。

| 网络名 | 模块焊盘 | GPIO | 接到 | `config.h` |
|-------|---------|------|------|-----------|
| SCL | 20 | IO12 | 屏幕插座 U4.5 | `TFT_SCLK` |
| SDA | 19 | IO11 | U4.4 | `TFT_MOSI` |
| CS | 18 | IO10 | U4.2 | `TFT_CS` |
| DC | 16 | IO46 | U4.3 | `TFT_DC` |
| RES | 17 | IO9 | U4.1 | `TFT_RST` |
| EC11A | 24 | IO47 | 编码器 SW1.A | `ENC_PIN_A` |
| EC11B | 25 | IO48 | SW1.B | `ENC_PIN_B` |
| EC11KEY | 26 | IO45 | SW1.E（按键） | `ENC_PIN_SW` |
| BOOT | 27 | IO0 | 轻触开关 SW3 → GND，R10 10kΩ 上拉 3.3V | `BOOT_BTN_PIN` |
| EN | 3 | EN | 复位键 SW2 → GND，R9 10kΩ 上拉 + C8 1µF | — |
| USB_DN / USB_DP | 13 / 14 | IO19 / IO20 | USB-C D− / D+（原生 USB，所以 PCB 要开 `ARDUINO_USB_CDC_ON_BOOT`） | — |

- **屏幕插座 U4**：1×7P 2.54mm 排母，依次 RES/CS/DC/SDA/SCL/GND/3.3V，**没有 BLK**（`TFT_BLK = -1`，背光常亮、不能调光）。屏幕装配方向跟开发板差 180°，`TFT_ROTATION = 2`（实测画面摆正）。
- **BOOT / EN 键**：PCB 上都有，接法跟 DevKitC 一样。长按 SW3 5 秒清除配对，跟开发板上长按 BOOT 键相同；烧录后需按 SW2（EN）复位才运行新固件。
- **编码器硬件消抖**：A/B/SW 三根线都是 10kΩ 上拉 3.3V（R1/R3/R5）+ 100Ω 串联（R2/R4/R6）+ 100nF 对地（C1~C3），RC 约 1ms。固件里的 `INPUT_PULLUP` 跟外部上拉并联，不冲突。
- **供电**：USB-C（16P）CC1/CC2 各 5.1kΩ 下拉（R7/R8），5V 经 AMS1117-3.3（U2）降压。去耦：5V 侧 10µF + 100nF（C4/C6），3.3V 侧 22µF + 10µF + 2×100nF（C9/C5/C7/C10）。
- **模块**：`ESP32-S3-WROOM-1-N16R8`（带 PSRAM，VDD_SPI 由 eFuse 固定 3.3V，见本节开头的 GPIO45 说明）。
- **残留记录**：工程的器件库里还留着一个 1×8P 排母（LAIL-PM2.54-8P-L）的定义，PCB 文档里也有 8 条指向已删除器件的空焊盘记录。原理图和 PCB 上都没有这个器件，不影响生产。

## 3. 固件方案（复用 X-Knob，适配 EC11 + 本地模拟回显）

### 3.1 复用什么（从 X-Knob 抽取）

| X-Knob 资源 | 用途 | 最小调试是否要 |
|------------|------|--------------|
| `lib/lvgl/`（自带完整 LVGL 8） | UI 框架 | ✅ 要 |
| `src/port/display.cpp` + `lv_port_disp.cpp` | GC9A01 屏幕驱动接线（Arduino_GFX） | ✅ 要 |
| `src/port/lv_port_indev.cpp` | 把旋钮/按压接进 LVGL 输入设备 | ✅ 要（改造为 EC11） |
| `src/hal/lcd.cpp` | 背光 PWM + 亮度调节 | ✅ 要（可选） |
| `src/app/Pages/SurfaceDial/*` | 圆形仪表盘 UI 参考 | 🔧 改造 |
| `src/app/Utils/PageManager/*` | 多页面框架 | ⏸ 最小版可不引入 |
| `src/hal/encoder.cpp` | 编码器开关使能 | ✅ 要（改造） |
| `src/hal/motor.cpp`、SimpleFOC、3205 电机 | 力反馈 | ❌ 不要（EC11 无电机） |
| MQTT / WiFi / OTA | 联网 | ❌ 最小版不要 |

### 3.2 关键改造点（EC11 替代电机编码器）

X-Knob 用 **无刷电机 + MT6701 磁编码器** 给 LVGL 提供旋钮输入。换成 EC11 后：

1. **LVGL 输入层**：`lv_port_indev.cpp` 的 `encoder_read()` 里，
   把 `HAL::get_motor_position()` 替换为 **EC11 的 A/B 相增量计数**。
   旋转 A/B → `data->enc_diff++ / --`；按压 SW → `data->state = PR/REL`。
2. **按压检测**：复用 X-Knob 的 `HAL::encoder_is_pushed()` 逻辑
   （读 SW 引脚，`INPUT_PULLUP`，按下低电平）。
3. **去掉电机**：不调用 `motor_init()`、不引入 SimpleFOC、删掉力反馈相关代码。
4. **UI 数据源**：屏显值用**本地变量模拟**（见下节），不做 BLE、不连车机。

### 3.3 本地模拟回显逻辑（最小版）

先做一个简单的**单页面 UI**，模拟"车控功能"交互：

```
屏幕显示（从上到下三个 LVGL 控件）：
  1. 功能名 label，如"功能: 温度"
  2. 数值 label（大号数字），如"22.5 °C"
  3. arc / bar，显示当前值在范围内的位置

交互：
  单击（短按）EC11  → 在 [温度/风量/座椅加热] 之间切换功能
  旋转 EC11        → 调节当前功能的数值（温度±0.5℃、风量档位…）
  长按 EC11        → 回到主菜单 / 确认
```

- 数值只存在**固件内存变量**里（`float temp = 22.5; int wind = 3;`）。
- 每次旋转/点击后刷新屏幕 label。
- 这条交互链验证通过 = **硬件 + LVGL + 旋钮输入**全部成立，之后接 BLE/车机只改数据源。

## 4. 分步验证（从易到难）

| 步骤 | 验证内容 | 通过标准 |
|------|---------|---------|
| 1. 上电 | 开发板 USB 供电，串口能打印 | 串口监视器看到 boot 日志 |
| 2. 点亮屏幕 | 屏显示纯色/默认 LVGL demo | 圆形屏正常显示画面 |
| 3. 屏幕 UI | 显示"温度/风量"布局 | label、arc 正确渲染 |
| 4. 旋转 | 旋转 EC11 → 数值变化 | 屏幕数值随旋转增减 |
| 5. 按压 | 单击切换功能、长按返回 | 功能随按压切换 |
| 6. （二期）BLE | HID 键盘 + GATT 回显 | 车机 App 收到按键/旋钮事件 |

> 到第 5 步 = **最小硬件调试目标达成**。此时硬件链路、交互逻辑、屏幕回显全部可用。

### 5.1 固件版本号与更新方式（后来加的）

- 版本号 = `firmware/VERSION`（人工维护，如 `0.1.0`）+ 编译时自动拼上的 git 信息，例如 `0.1.0+c8cd265`；有没提交的改动时是 `0.1.0+c8cd265.dirty.2c3994a`。规则见 `firmware/scripts/version.py`，开机串口打印 `[Knob] boot, firmware <版本> (<板子>)`。
- 发版时改 `VERSION`，不改也行：代码一变版本号就跟着变，插件照样会认为不一样、触发升级。
- **USB 刷写**：`cd firmware && pio run -e pcb -t upload`（开发板用 `-e devkit`），刷完按 EN 复位。
- **OTA**：旋钮上的固件支持 OTA 之后（2026-10-22 起的固件都支持），更新只需要在车机/手机上导入新的插件包（`plugin/` 下 `./gradlew pluginPackage`），插件连上发现版本不一样会自动推送固件，约 80 秒。从不支持 OTA 的旧固件升级，必须先用 USB 刷一次。
- 暂不支持回滚：新固件能启动但有问题时，导入一个带旧固件的插件包降级；新固件起不来、连不上蓝牙时只能 USB 刷。

## 6. 下一步（本方案跑通之后）

1. **接 BLE HID**：复用 X-Knob `lib/ble_kb`，把"旋转/按压"上报为 Dial/键盘事件。
2. **接真实车况回显**：在旋钮固件加一个 GATT Write Characteristic；车机 App 用现有
   GattClient 把 BYDAUTO 读到的空调/座椅状态写回，屏幕显示真实数据。
3. **产品化**：再考虑锂电池、TP4056、3D 外壳（可参考 X-Knob `2.Model_3D/`）。
