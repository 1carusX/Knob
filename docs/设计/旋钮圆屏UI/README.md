## 驾驶数据

车速、油门深度、刹车深度三项**只读**展示：拧旋钮不改任何东西，也没有「长按确认」，所以不会出现琥珀色。数据来自车速设备（`BYDAutoSpeedDevice`）的监听：车速 0~282 km/h（SDK 的 `SPEED_MAX`），油门/刹车深度 0~100%（`DEEP_PERSENT_MAX`），插件已经注册了监听（`CarControl.onSpeedChangedExternal` 等），还没接到旋钮上。

⚠️ 实车上车速设备目前还初始化不了（缺 signature 级 `BYDAUTO_SPEED_GET`，见 `docs/验证结论.md` #13、#14），重签后能读到数据，这些画面才有意义。

驾驶页**不是双击循环里的停靠点**，是旋钮闲置时的待机画面（进出规则见下面「进出」），画面上**没有标题**：
- **中间只有车速**：92px 大数字，不带单位，竖直居中在圆心。三位数（≥100）也放得下。
- **整圈刻度环从正上方分开**：跟温度环同样 270°、缺口朝下。正上方 270° 一根 0% 刻线（r 99→117、线宽 2、`#8A93A0`，同座椅「关」那根）；往右顺时针是**油门**（绿 `#34D399`），走到右下 45°；往左逆时针是**刹车**（红 `#F0414D`），走到左下 135°。每边 0~100% 各占 135°，每 5% 一根刻度（整 25% 的 r 100→113、线宽 2.4，其余 r 104→113、线宽 1.6），踩下去的部分着色，没踩的 `#2B313A`。当前值处一个同色亮点（r 93，同温度环亮点），0% 时不亮点。两个踏板同时踩也能同时显示。
- **环的头尾是两个百分比读数**：刹车在左下（环的头）、油门在右下（环的尾），数字 22px + `%` 13px，中心在 r 98、角度 118°（刹车）/ 62°（油门），刚好落在缺口两侧、各自那半环的末端旁边。踩着时用各自的颜色，0% 时变暗（`#4A515C`）。
- **读不到数据**（权限不够、设备初始化失败、监听没来过数据）：车速显示 `- -`（`#4A515C`）、环全灰、两头读数不显示，不加文字说明。

### 进出

- **进入**：在停靠点画面（联动 / 分控 / 座椅）上 **10 秒没有任何操作**，自动切到驾驶页。转动、单击、双击、长按都算操作，每次操作重新计时。超时的时候如果还有没提交的改动（琥珀色），直接丢掉——它本来就没发给车机，车上什么都没变。
- **退出**：在驾驶页上**第一次操作**（转动、单击、双击、长按都行）回到原来的页面，也就是进驾驶页之前停着的那个停靠点、那个子项（座椅的哪个座位、分控的哪一侧），显示的是车上当前的值。**这一下只用来唤醒，不执行**：单击不会切座位、双击不会跳停靠点、长按不会提交、转动不会改数值。回去以后重新开始计时。
- **没有原来的页面**（刚装好、插件里还没存过停靠点）时回默认页「联动」。插件会把停靠点存下来（`KEY_PAGE`），重启车机后也算"原来的页面"。
- **不进驾驶页的情况**：连接 / 配对 / 等待连接 / 固件升级这些系统画面不受超时影响；长按提交进行中不计时；插件从来没发过车速数据（实车读不到车速，比如没有 `SPEED_GET`）时也不跳——跳过去只能看到 `- -`。已经在驾驶页、后来数据断了，才显示无数据画面。
- **10 秒**是先定的值，固件里一个常量，真机试过再调。

**为什么计时放在固件里**：旋钮转动只改固件本地的值，不上报给插件（长按确认才把结果带过去），插件根本不知道用户在拧。所以闲置计时、切到驾驶页、唤醒回原页都由固件自己做，**插件里的当前停靠点（`currentPageId`）一直不变**——"原来的页面"天然就是插件那边的当前停靠点，不用另外记。车机触屏上的操作照常同步给旋钮，旋钮在驾驶页时只更新存着的数据、不跳回去（看触屏的人不会同时看旋钮），等旋钮自己被操作时再回去。

颜色语义：绿色原本只表示「成功 / 升级」，红色原本是座椅加热 2 档 / 温度最热端；在驾驶页里绿 = 油门、红 = 刹车，跟车上的习惯一致，没有引入新颜色。

实现（固件 `firmware/src/main.cpp`，插件 `MainPlugin.kt` 的「驾驶数据」一节）：
- **固件**：`DIAL_DRIVE` / `redraw_drive()` 画驾驶页；`update_drive()` 做闲置计时（`DRIVE_IDLE_MS` = 10 秒）和唤醒，唤醒看的是消抖后的按键状态（`encoder_is_button_down()`，抖动、干扰不会误唤醒）；按下按键唤醒时 `s_swallow_button` 把这一下的单击/双击/长按全部丢掉，也不画长按进度环，一直丢到旋钮模块彻底空闲（`encoder_is_idle()`：松手、单击不再等双击窗口、事件都取走了）——按状态判断不靠定时器，`loop()` 偶尔卡一下也不会漏。
- **字体**：两头读数新生成了 `font_num_22`（等宽数字 `0123456789`，同样先过 `freeze_tnum.mjs`）和 `font_num_13`（只有 `%`）；`-` 本来就在 `font_num_92` 里。画面上没有中文，`font_zh_*` 没动。
- **插件推送**：驾驶数据是单独一种消息 `{"speed": 62, "throttle": 28, "brake": 0}`（`speed` 整数 km/h，踏板 0~100，读不到车速时不带 `speed`），不管旋钮显示哪页都推，固件存着最新一份；数值变了才推、最多 5 次/秒，旋钮刚连上补推一份。`BleManager.write` 的排队按消息种类（`slot`：停靠点 / 亮度 / 驾驶）分开，各留最新一份，频繁的驾驶数据不会把停靠点同步顶掉。
- **数据源**：启动自检通过后，`SPEED_COMMON` + `SPEED_GET` 都授权了才初始化车速设备、注册监听；缺权限或初始化失败就不推，旋钮不会切到驾驶页。之后申请到权限会自动再试。模拟版插件用假数据（8 秒一个周期，车速 10~110 起伏，加速踩油门、减速踩刹车），手机上配 `generic` 壳就能看到驾驶页。
- **模拟器**：`firmware/simulate` 多出 6 张驾驶页截图（含唤醒后回到联动、没提交的改动被丢掉），并检查按键唤醒的那一下不会发给手机。

## 固件实现

已在 `firmware/src/main.cpp` 按本设计实现（`build_ui()` / `dial_draw_cb()` / `redraw_*()`），V1 板（`pcb`）真机跑过一轮，按反馈修改后待复测。

- **环、刻度、图标**：没用 `lv_scale`/`lv_arc`，所有环、刻度、亮点、座椅分页标记、蓝牙/对勾线条图标都在一个全屏透明对象的绘制回调 `dial_draw_cb()` 里按状态用 `lv_draw_line`/`lv_draw_arc`/`lv_draw_rect` 现画；等待连接/等待数据的转圈也在这里画（`draw_spinner()`），不用 `lv_spinner`：照 Material 3 Expressive 的算法，6 秒一个周期、首尾无缝（`s_spinner_style` 还留着 Material 经典款可切换）。长按提交/清配对进度环是独立的叠加层（`s_overlay_percent`），`redraw()` 不碰它。
- **未提交状态**：沿用 `s_value != s_synced_value` 判断，表现为琥珀色数字 + 空心原值点 + 「长按确认」；按住出进度环后提示换成「继续按住」。
- **字体**（`firmware/src/fonts/`，`lv_font_conv` 1.5.3，4bpp，不压缩，不勾 `--lcd`，生成参数见各文件开头的 Opts；许可证 `OFL-*.txt` 同目录）：
  - 数字 Barlow Semi Condensed Medium：`font_num_92`（大数字）、`font_num_80`（分控编辑侧）、`font_num_44`（分控参考侧、配对码）、`font_num_34`（设备名，符号集 `Knob-0123456789ABCDEF`）、`font_num_28`（只有 `%°`）、`font_num_22`（驾驶页两头的百分比数字）、`font_num_13`（驾驶页百分比后面的 `%`）。
  - `font_num_92` / `font_num_80` / `font_num_44` / `font_num_22` 用的是**等宽数字**（tnum）：Barlow 默认是比例数字，「1」比「0」窄 16px（80 号），分控拧动时数字宽度一变、两列整体居中就跟着左右跳。`lv_font_conv` 不套用 OpenType 特性，所以先用同目录的 `freeze_tnum.mjs` 把 tnum 字形固化进 cmap（`node freeze_tnum.mjs BarlowSemiCondensed-Medium.ttf BarlowSemiCondensed-Medium-tnum.ttf`，只用 Node 自带模块；生成字体本来就要 Node 跑 `lv_font_conv`），生成 `BarlowSemiCondensed-Medium-tnum.ttf`，再用它生成这几份（文件开头 Opts 里的字体名就是它）。
  - 中文 Noto Sans SC Medium：`font_zh_13` / `font_zh_16` / `font_zh_20` 共用一份字表（字表外字符回退到 `lv_font_montserrat_18`），`font_zh_28` 只有座位名「主驾副左后右」（字表外回退到 `font_zh_20`），`font_zh_44` 只有「关」。
  - 原始字体文件不入库，要重新生成时先下载：Barlow 用 Google Fonts 仓库的 `ofl/barlowsemicondensed/BarlowSemiCondensed-Medium.ttf`（github.com/google/fonts），Noto Sans SC 用 `Sans/SubsetOTF/SC/NotoSansSC-Medium.otf`（github.com/notofonts/noto-cjk）。命令照各文件开头的 Opts 用 `npx -y lv_font_conv@1.5.3 …` 跑；数字三份先过一遍 `freeze_tnum.mjs`。
  - ⚠️ 新增上屏中文要把字补进三份 `font_zh_*` 的 `--symbols` 重新生成，缺的字直接显示不出来。生成后把文件开头的 include 段换成带 `__has_include` 的写法（1.5.3 默认只认 `lvgl/lvgl.h`，PlatformIO 和 `firmware/simulate` 都找不到）。
- **分控副驾反向拧**：分控编辑副驾（`ac_split_deputy`）时，`loop()` 里把旋钮的转动量取反，逆时针升温，跟镜像的右半环方向一致。只在固件本地做，插件不知道这回事。
- **跟设计稿的小差别**：中文正文字号合并成 13/16/20 三档（设计稿里的 15px → 16、18px → 20；座椅座位名单独一份 28，跟设计稿一致）；「请在手机上确认」用的 Medium 字重（设计稿是 400）。
- **对照验证**：`cd firmware/simulate && cmake -B build && cmake --build build -j` 会用真正的 `main.cpp` + LVGL 在电脑上渲染全部状态（`firmware/simulate/out/`），改完固件先跟本设计稿对照，不用每次烧板子；`--target anim` 出动画。用法见 `firmware/simulate/CMakeLists.txt` 开头。
- 插件推送的数据格式没改：座椅的「加热/通风」由 `value` 正负决定，分页标记由 `sub_count`/`sub_index` 决定；分控画面的标题由固件写死「分控」（不用插件发的 `title`），主驾/副驾标签画在数字下方。
